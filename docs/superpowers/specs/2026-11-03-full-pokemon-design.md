# 全量宝可梦学习探险设计

## 用户目标与验收

1. 全部接入 PokeAPI 当前宝可梦物种及形态，提供本地图片、兼容 iPhone 的叫声、中文介绍、属性和进化关系。导出来源与覆盖审计，不能把缺资源的条目宣称完整。
2. 关系图可点击任何节点查看该形态资料、收藏和上下游。进化与同物种形态变化分开标注，不能把超级进化算永久第三次进化。全家族覆盖，不仅第一世代。
3. 保持识字、英语阅读两项必选。两项可选默认「完成8篇英语作业」「识字10个」，开始前可编辑。学习开始后锁定当天约定，防止临时加量。
4. 按用户后续确认，识字组（必选任务0↔可选任务3）、英语组（必选任务1↔可选任务2）每天各领取一次。每组必选完成可领1普通球，本组必选＋对应可选完成可改领2普通球或1大师球；任一方案领过后该组所有领取按钮保留、灰色、显示「已领取」，不能补领或改选，另一组不受影响。两球奖励一次入库，依次揭晓。两个账号规则相同。
5. 新的每日相遇使用数组，逐次保存时间、学习来源、球种和实际抽取权重；兼容已有单次 encounter 记录，不能丢失收藏或重置已领日。
6. 两个孩子（马亦谦、马熠初）学习、机会、选择、抽取历史、重复降权、备份分别隔离。数据库明确各自独立，不能仅声称同表 user_id 是两套数据库。禁止跨账号导入。
7. 图鉴每张已拥有卡片右下角显示数量，详情列出所有抽取经历；允许重复，单个已拥有形态权重变为未拥有的 0.5，不随数量继续减半。父子进化形态分别计数。
8. 首页去掉动画预览入口，保留进入学习探险与图鉴。金球使用已验收的实体球壳、固定后铰链，增加金色材质、大师球标记和配套出场灯光与声音；普通球继续现有动画。
9. 手机主导操作；图鉴分页、检索、属性/分类/家族筛选，避免一次渲染千余卡片。筛选、切换账号后页码回到首页。关系图完整可交互。

## 分类与概率（用户最新修订）

常见名单按小智、小刚、小霞、武藏、小次郎历代曾收服／拥有的伙伴与喵喵整理；历史进化、寄养、放生保留，借用及只结伴未收服排除。完整名单见 `docs/pokemon-common-roster.md`，代码源为 `pokemon-trainers.js`，去重并排除稀有特殊档后167个形态。小智的美录坦、美录梅塔仍属于幻之，仅大师球可抽。

分别保存「熟悉的角色伙伴」与实际物种阶段。普通球中前者优先归常见档；大师球则按真实进化阶段分池，保证喷火龙等熟悉伙伴也可以从大师球获得。超级进化、幻之、传说标记始终优先，其余按源 species ancestry 递归阶段分类。

| 档位 | 普通球 | 金球 |
|---|---:|---:|
| 常见 |20%|0|
| 基础 |50%|0|
| 进化一次 |20%|55%|
| 进化两次 |10%|30%|
| 传说 |0|5%|
| 幻之 |0|5%|
| 超级进化 |0|5%|

先抽档位，再按该档内权重选形态。已拥有乘0.5，归一化后抽取；不随重复次数继续递减，不改变公示档位概率。金球的阶段保底对非传说、非幻之、非超级进化条目成立；特殊稀有档可无普通进化链。所有抽取由服务端生成随机数，CAS更新防并发多领；本机预览共用同一核心规则。

## 数据与资源策略

使用 PokeAPI 官方源码仓库 CSV（与其 API 同源）批量生成本地静态数据，避免页面打开时向 API 发千余请求。保存来源、时间、原始表行数和每项资源覆盖结果。中文名优先简体，介绍优先官方中文 flavor text；缺中文原文时用源资料的属性、分类与进化事实生成标明为「资料摘要」的中文说明，保留原文与语言，不编造官方介绍。进化条件源自 pokemon_evolution，不以高度体重猜测。

默认形态与特殊形态均保留独立 Pokémon ID。关系图以物种进化为主干，同物种其它形态为带类型说明的分支；用明确的「形态变化」连线。所有条目参与图鉴与抽取分类。

## 验证证据

- 数据覆盖测试：每个 API 条目有唯一 ID、来源、合法分类、图片和可解码音频；所有物种出现，全部关系双向一致，无环、无悬空节点。
- 核心测试：基础/额外资格、分组领取、三方案互斥、禁止补领、两球原子入库、跨日、重复、旧数据兼容、分类/权重边界和失效输入。
- 服务端测试：两套真实数据库实例，相同日期互不影响；并发选球/领取只成功合法次数，切换请求不能混写。
- UI 验证：手机可编辑默认任务，选择金球/两普通球、数量角标、重复明细、查找各世代及分支/超级进化、账号往返、首页无动画按钮、金球完整开盖、可跳过与声音。
- 只在上述要求全部有当前证据时标记总目标完成。部署状态和本机状态分别报告。
